# Agent / Worker / Sandbox 修复执行方案

日期：2026-09-16。依据：[审查报告 R1–R6](README.md)。状态：待实施；本文不表示生产代码已经修复或验收完成。

## 范围与工作方式

- 本轮仅形成计划。实施时以当时 HEAD 和工作区重新确认基线，保留现有模型、Compose 等在途修改；重叠文件只修改本任务相关段落，禁止整体覆盖或批量提交。
- 顺序执行，不启用多 Agent。执行者负责代码、共享构建栈、回归和验收；每个 PR 独立说明改动、复现、验证及遗留限制。
- 保持 MySQL 为 Run 权威、BFF 为薄转发、exec 为字节和进程权威。不改冻结的 `docs/plan.md`。
- 使用 runtime-versions.json 指定版本。安全隔离、跨租户 404、常量时间令牌比较、非 root 和有界出站超时全部保留。

## 阶段 0：先建立失败基线

1. 将 probe.mjs 中确认缺陷的断言转成对应测试目录中的“预期正确行为”回归；先记录它们在修复前失败。
2. R1 使用独立临时工作区、低资源阈值及外层限额复现，不向现有数据卷填盘、不运行无界 fork bomb。保留额度内成功的对照。
3. R2 使用真实 HTTP + bwrap 执行超过 15 秒的命令；用隔离文件记录命令结束/取消后的写入，核对客户端失败是否留下执行。
4. R3 用真实 MySQL/Redis/BullMQ 和受控 executor 屏障，确保父 Run 全部占槽后再创建子 Run；保存 active/waiting 状态，证明槽位饥饿。替身只控制任务进度，不替换事务和队列。最终再跑真实模型工具链。
5. R6 连续产生有限总量输出，不调用 readOutput，记录保留字符数；避免依靠 OOM 才认定失败。

退出条件：每项有失败测试或真实请求证据；无法复现项保留为待验证，不按猜测直接修改。

## PR 1：恢复 sandbox 资源与配额约束（R1）

主要边界：`exec/src/http/app.ts`、`workspace/env-config.ts`、`workspace/child-quota.ts`、`shell/executor.ts`、`shell/process-runner.ts`、`isolation/*`、Compose/部署配置。

执行步骤：

1. 建立现有资源配置→消费者清单，严格校验范围和单位，移除 1024 MB 硬编码，控制面使用现有 quota 配置入口。
2. 在共享进程执行链接入现有配额准入与 watcher，覆盖前台、后台、Python 和 MCP 可达的执行入口。创建后超额、测量失败、执行结束、取消和 spawn 失败都必须清理进程/监控器。
3. 生产启动调用现有硬配额校验。运维声明和真实项目/卷额度分开验证；不能把声明设 true 当作部署验收。
4. 将进程数/文件描述符/CPU 时间/文件大小等限制传到实际 launch。核对 Linux 对 RLIMIT_NPROC 的真实 UID 计数范围，不能将同 UID 共享限额宣传为逐工作区限额。
5. 内存限制必须明确是地址空间还是进程树总量；容器总量只作为服务兜底，不能冒充逐任务额度。若已有部署能力无法实现某项承诺，明确报错并保持该项验收开放，不新造一套资源调度平台。

验收：额度内正常命令成功；低阈值超限命令及其后代停止；另一个 owner 的正常命令仍成功；正配额缺监控/硬额度声明时生产拒启；重启后账本额度一致。对新启用的 500 MB 配置，先盘点已用量，超额工作区不删数据，按统一超额策略限制新增写入。

## PR 2：打通 Shell 请求、deadline 和取消（R2、R4）

主要边界：`contract/`、Agent `remote-shell.ts`/`exec-rpc.ts`、exec `internal-shell.ts`/`node-listener.ts`/executor/runner。

先锁定契约：

| 字段/行为 | 处理规则 |
|---|---|
| workdir | 缺省为工作区根；逻辑路径经现有路径策略转换，允许目录根范围按既有隔离契约确定；越界、无效类型不能静默退回根目录 |
| stdin | 缺省无输入；保留空字符串与非空输入语义，明确写入结束是否关闭 stdin |
| env | 仅允许校验后的请求覆盖值，经现有 safe-env 过滤；宿主服务凭据不能透传 |
| stdoutMaxBytes | 严格按字节解释，受服务端上限约束；覆盖多字节字符跨 chunk，正确报告 truncated/lossy |
| timeoutMs | 有限整数，受服务端执行预算限制；客户端执行等待 deadline 为最终预算加有界回传余量 |
| AbortSignal | 不序列化成布尔值代替取消；客户端 signal 与 transport deadline 合并，服务端连接断开传到前台执行 |
| 错误 | 复用现有契约错误；非法字段在执行前拒绝，超时/取消与业务非零退出可区分 |

实施注意：

- run/start 共用字段解析与安全校验；后台 start 仍按异步进程契约运行，不能因为“启动响应已结束”就杀后台进程。
- Node listener 正确识别请求中断/响应连接提前关闭；不能把正常 request body 读完的 close 事件误判为取消。成功结束时移除事件监听。
- 前台取消进入 runner，确认终止整棵隔离进程树；处理“取消先于 spawn”竞态。断网未被及时感知时，执行预算仍提供有限上界。
- 工具调用失败不自动重试非幂等命令；若响应丢失而执行结果无法判定，保留未知结果语义，不宣称 exactly-once。

验收：20 秒任务在 120 秒预算内成功；短预算超时停止写入；主动取消/连接断开后无残留写入；正确 cwd/stdin/env 实际生效；越界 cwd 和非法字段被拒绝，合法对照成功；前后台输出上限与 Unicode 正确。

## PR 3：保证子 Run 有可用消费槽（R3）

拟采用方案：基于已有 `subagent_depth` 和有限最大深度，为各层使用独立 BullMQ 队列与保留消费槽；消费者仍在现有 agent-worker 进程内。先完成阶段 0 的真实队列实验，再与冻结架构核对兼容性并新增未占号 ADR 锁定决定，之后编码。

选择依据：当前只有 WAITING_APPROVAL / WAITING_INPUT，没有通用子任务停泊与恢复协议。复用前两者会混淆对外状态；新增完整 park/replay 会涉及状态迁移、持久化 continuation 和模型重放。本次优先保留当前前台等待语义，用有限深度保障队列进展。

具体约束：

1. 每个允许深度至少有一个专属槽；根任务不能占用深层保留槽。并发总预算要显式定义，不可悄悄按层翻倍。以当前最大深度 2、总预算 4 为例，可分配 2/1/1，代价是根任务同时执行量从 4 降至 2；部署文档必须说明。
2. 仅拆“父队列/子队列”不够：深度 1 的子任务也会等待深度 2，因此按完整有限深度分层。配置预算不足、深度不合法或某层消费者缺失时拒绝接新任务/标记不就绪。
3. 在唯一 enqueue adapter 按 MySQL Run 的权威深度选择队列，不能信任模型提交的队列名。持久化 queue_name 与实际目的地保持一致；普通创建、cron、子任务、审批/交互恢复、失败恢复全部走同一规则。
4. 保留 runId 和 resume 专用 jobId 的既有幂等约定，以及 lease/fence/cancel。深度上限变更必须同步容量约束。
5. dependency guard、readiness、shutdown、监控覆盖所有消费者；任何一个必需层失效不能仍报告整个 Worker 就绪。
6. 迁移采用受控停收与排空：旧任务排空后切换路由；无法排空的旧队列任务必须有迁移清单，保持 runId、核对账本并去除旧副本。禁止新旧消费者同时重复搬运。回滚也先停止投递、处理分层队列存量，不能只换回镜像。

验收：根槽全部占满后子任务仍执行；深度 1 全部等待深度 2 时仍可完成；父子取消、跨租户查询、消费者暂停、Worker 重启、入队失败恢复、审批/交互恢复全部正确。若有限深度容量实验不能证明进展，则暂停此 PR，重新设计持久化 park/replay，不能靠提高并发掩盖。

## PR 4：收敛子任务轮询（R5）

- 在现有 provider 修复 timer、abort listener 的对称释放；正常完成、取消、dispose、store 抛错均恢复监听器基线。
- 采用有界退避，建议 200 ms 起、最多 2 s；取消不等待轮询周期。先用标准定时器能力，不增加事件总线或新依赖。
- 验证取消与结果同时到达的竞态、错误传播；测量固定等待时长的查询次数，记录改前/改后及结果发现延迟。
- 不改变持久化结果和租户校验语义；如果后续必须亚秒唤醒，再评估复用已有 durable 事件。

## PR 5：限制 Agent 后台输出缓冲（R6）

- 限制 RemoteShellProcess 未消费缓冲，使用现有上限及 lossy 语义；明确保留尾部与 readOutput 后的清空规则，跨 chunk 不重复、不破坏字符。
- 不从 Agent 导入 exec 内部实现来复用类；两侧若语义不同，用本地最小有界截断即可，不额外建立公共缓冲框架。
- 验证持续输出且不读时缓存有界、读后可继续收取、终态最后一批输出可见、监控停止；累计输出至少超过缓冲上限十倍但测试总量有限。

- 每个阶段：失败基线 → 最小修复 → 相关回归 + 所涉包类型检查；失败修正后重跑受影响检查。
- 每个代码 PR 最终交付：六套测试、exec/contract/BFF/Agent 类型检查、前端 build；涉及 Compose 再验证渲染配置，日志不输出密钥。
- 运行路径修改必须按 AGENTS.md 重建 agent、agent-worker、api-server、sandbox、sandbox-mcp，并确认运行容器已换新镜像；串行操作共享栈。
- 每个运行路径 PR 做本次专项真机验证，加登录 → 建会话 → 带工具 Run → logs/signal → 跨租户 404；若接口/UI 受影响，另做真实浏览器保存/错误/冲突路径。
