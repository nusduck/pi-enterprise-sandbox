# 真实资料、预期结果与证据

## 1. 数据来源与冻结

以下为执行前的准备规范，**不是已经采集或测试通过的声明**。执行人先建立 `rt-YYYYMMDD-<批次>` 资料包，再进入浏览器；原始资料与独立验算结果分别保管。模型不能通过读取验算答案完成任务。

| 数据包 | 来源与准备 | 实际用途 | 不得声称 |
|---|---|---|---|
| R：真实项目资料 | 在本轮冻结 commit 导出 `README.md`、`docs/api.md`、`docs/webui.md`、`docs/development.md`、`docs/STATUS.md`、相关源码；需覆盖 dirty 改动时仅导出允许清单中的当前文件，逐个记 hash 和基线差异；另导出最近 30 个提交的 SHA、时间、标题和文件变更（不含作者邮箱） | 新同事交接、版本周报、变更影响排查、搜索、多轮问答、办公报告 | 文档里的历史“通过”等于当前通过；提交次数等于生产力；不存在的客户/营收 |
| W：官方公开指标 | 世界银行 WDI，固定 `SGP`/`MYS`/`IDN`，2019–2023，指标 `SP.POP.TOTL` 与 `NY.GDP.MKTP.CD`；保存原始 JSON、指标元数据与规范化 CSV | 区域市场资料初筛、年度趋势、口径澄清、Excel 与图表、报告和演示 | GDP 等于销售额/市场规模；名义美元变化等于实际经济增长；缺失值等于零 |
| V：真实视觉资料 | 从 W 的已独立核验图表导出 PNG，并截图真实浏览器界面（如上传失败/审批页，先去除身份和凭据）；保存底层数值或文字对照 | 图表理解、粘贴图片、截图排障、模糊图片边界 | 人工画的“成功”截图代表产品实测；模型识别对了颜色就代表读懂数据 |
| U：可选业务资料 | 仅使用用户明确授权的脱敏订单/退款/产品字典、需求说明、会议记录或现有 Office 文件；记录脱敏与授权范围 | 订单对账、需求到交付、既有文档修改 | 本轮已经取得此类资料；模型补写的流水是真实交易 |
| X：显式构造的边界夹具 | 从 R/W 的副本派生同名文件、损坏归档、缺失/重复行、假密钥探针；容量测试可重复真实行，但保留生成规则 | 故障、幂等、安全、容量与清理 | 派生数据仍是官方原始记录；重复放大数据的业务统计有现实意义 |
| S：合成日常工作包 | 按 §6 明确定义订单/退款、会议记录和会后修订；文件标题和用户提示均标“合成演练” | 财务对账、会议待办、修订周报、Office 跨格式交付；可自备且无需真实客户数据 | 虚构身份是真实员工；演练金额是真实营收；场景答案证明真实业务数据已验证 |

公开数据调用方式已核对[世界银行 API 官方说明](https://datahelpdesk.worldbank.org/knowledgebase/articles/898581-api-basic-call-structures)。执行前分别请求：

- [人口数据](https://api.worldbank.org/v2/country/SGP;MYS;IDN/indicator/SP.POP.TOTL?date=2019:2023&format=json&per_page=1000)
- [现价美元 GDP 数据](https://api.worldbank.org/v2/country/SGP;MYS;IDN/indicator/NY.GDP.MKTP.CD?date=2019:2023&format=json&per_page=1000)
- [人口指标定义](https://api.worldbank.org/v2/indicator/SP.POP.TOTL?format=json)与 [GDP 指标定义](https://api.worldbank.org/v2/indicator/NY.GDP.MKTP.CD?format=json)

必须检查响应状态、分页、指标/国家/年份和单位，不能把错误 HTML 当数据。保留 `lastupdated` 等源元数据；官方历史数值可能修订，本轮全部案例用同一份冻结文件比较，不在案例里编写未经取数验证的“标准数值”。来源不可达且没有可核验缓存时，W 相关案例阻塞；R 主线仍可执行，但不得宣称公开数据链路通过。

每个资料包建立 manifest：来源 URL 或 repo path + commit、获取时间、字节数、SHA-256、编码、文件名、行数/页数、字段/单位、原始/脱敏/派生类别、派生方法。文件放 `.runtime/` 或系统临时目录，不能把 `.env`、数据库备份、整个工作目录或含凭据日志直接上传。资料不足时记录不足，不补造原始事实。

## 2. 执行前独立验算

| 对象 | 验算办法 | 通过条件 |
|---|---|---|
| R 文档问答 | 执行人从冻结源码与文档登记服务边界、当前路由、Agent 绑定与版本规则；标出文档冲突 | 回复有文件/章节依据；冲突明确指出，未验证内容不包装成事实 |
| R 发布周报 | 独立导出选定提交区间、逐文件归属；固定 merge/时间/文件统计口径 | 提交 SHA、影响服务、事实可逐条追溯；不编造上线日期、客户影响和测试结果 |
| W 数据完整性 | 国家×年份×指标为目标网格，按原始响应登记实际条数、缺失和重复；CSV 保留来源 key | 三类数量各自一致；不默认 30 个数值都非空；重复不悄悄累加 |
| W 数值计算 | 用独立本地脚本或电子表格重算，不能复用被测 Agent 生成的计算脚本 | 原始数值不改写；衍生值按预先登记精度比较；如显示两位小数，差不超过半个末位单位 |
| W 趋势 | 年变化率 = `(本年值 / 上年值 - 1) × 100%`，缺失、无上年或零分母输出缺失原因 | 年序正确；不跨缺失年冒充同比；现价美元口径清楚，不推导实际增速/商业回报 |
| 多轮修订 | 登记用户最后确认的国家、年份、单位、受众和交付格式 | 后续回复/文件使用最后约定；不能改了文字仍沿用旧表格 |
| 文件快照 | 下载后独立计算大小和 SHA-256；与提交记录比较；再修改原 workspace 文件并重下 | 旧 Artifact 字节不变，新版必须新提交；不能只比较扩展名或页面 Ready |
| 运行与故障 | 浏览器、BFF/Agent 查询与 exec 作业账本交叉核对同一批 ID | 终态、输出、工具执行次数一致；没有任务已结束而账本永久 Running |

如果使用 U 订单包，先由执行人确定业务主键、订单状态、退款归属月份、币种与含税口径，再独立生成对账表。缺少退款/汇率数据必须保留待确认，不得默认补零或自行换算。U 是追加实务场景，不以缺少 U 阻塞 R/W 的全量功能测试。

## 3. 四类办公件逐一验收

使用当前产品实际提供的 `xlsx`、`docx`、`pdf`、`pptx` Skill；调用成功和交付件可用是两个断言。某 Skill 缺失/报错而 bash 降级生成成功，只能记录“交付成功、Skill 链路未通过”。

| 格式 | 最低交付内容 | 下载后的独立检查 |
|---|---|---|
| Excel | W 原始数据、指标定义、年度汇总、公式与趋势图分表；来源与数据时间可见 | 打开并重算；抽查首尾年和缺失值；公式无 `#REF!`/`#DIV/0!`；数值/日期类型、排序筛选、轴单位正确，不能只有一张图片 |
| Word | R 交接报告或 W 研究简报：摘要、事实与限制、表格、来源、后续行动 | 打开正文和表格，核对至少 3 个事实；标题层级和中文字体可读；修改指定段落后其余已核实内容保留 |
| PDF | Word 简报的定稿，保留表格和来源 | 逐页渲染检查缺页、截断、乱码、空白和遮挡；抽取正文对照 Word，不把“能解析 PDF”当排版通过 |
| PPT | W 管理层简报：问题、来源/口径、趋势、局限、建议行动（建议标明是建议） | 逐页打开/渲染；图表标签与 Excel 相同；文字可编辑，字号与边界可读；无虚构销量/排名和重叠溢出 |

四种格式分别记录 Artifact ID、下载文件 hash、打开/渲染工具与版本、内容核验结果。任一格式未做，TOOL-03 只能部分通过；不能以“至少两种”代表办公全量。

## 4. 证据记录模板

每个案例及其 a/b/c 子断言各记一行；新轮次初始一律未执行。新增证据文件独立带日期，不改写 `test-cases.md` §4–§9。

| 字段 | 应记录内容 |
|---|---|
| 基线 | 执行时间/时区、commit/dirty 状态、实际镜像 ID、部署模式、浏览器版本 |
| 身份 | 账号代号、角色、同 org/不同 org 关系；不记录密码或 Cookie |
| 数据 | R/W/V/U/X manifest ID、原始文件 hash、独立验算版本 |
| 操作 | 原始用户提示、步骤、输入选项、实际 Agent/version；所有推理请求 model=deepseek-flash 的脱敏证据（包括子任务/Cron/A2A/重试）；真实/故障注入/辅助协议方式 |
| 关联 | Conversation/Run/ToolExecution/Interaction/Approval/Process/Artifact/Cron/A2A task 的相关 ID |
| 断言 | 预期与实际，UI 现象、非敏感 HTTP 状态/错误码、必要的只读账本摘要、下载 hash |
| 结论 | 未执行/通过/部分通过/失败/阻塞；失败步骤、复现资料、阻塞依赖、证据位置 |
| 清理 | 本轮创建资源及保留理由，任务是否暂停、作业是否终止、测试凭据是否撤销 |

不能把 `SUCCEEDED`、页面截图、固定回显、工具声明或测试进程退出码单独作为业务任务通过证据。故障注入要记录注入点与恢复操作；模拟模型/MCP 只能作为补充契约证据。通过率以全部应执行子断言为分母，阻塞和未执行不能从分母里消失；适用性确实不成立的分支注明原因，不能隐藏需求缺口。

本轮执行不使用 fake LLM；旧 fake 模型 gate 的历史结果仅可作补充代码证据。记录原始失败后再重试，不把第 N 次成功覆盖前 N−1 次失败；同一无害自然语言任务可做一次明确工具要求的诊断重试，但两次结果均保留。普通任务的终态等待窗口、SSE 恢复窗口、guard/租约/取消期限从实际配置登记；CTX/LOAD/故障演练另设有界预算。超时不无限等待，也不临时放宽验收线。

## 5. 自建账号与资源清单

执行整轮时允许自建测试用户；本次文档编辑未实际建号。统一前缀 `rt-YYYYMMDD-<批次>`，用户名只用产品允许字符，密码每用户独立随机并安全保管。

| 身份 | 准备方式 | 用途 |
|---|---|---|
| admin-A | 专用环境管理员名单内注册/登录，服务端 me 确认为 admin | 配置、发布、回滚、A2A 凭据管理 |
| user-A | 普通注册，服务端 me 确认为 user | 数据分析、上传、Skill、定时任务 |
| user-B | 另一普通注册，独立浏览器 profile/隔离上下文 | 同组织不同 owner、并发办公；不以另一个共享 Cookie 标签代替 |
| user-C | 经环境支持的受信身份预置，明确不同 organization_id | 跨组织资源 404；无渠道则该分支阻塞 |
| admin-C | 第二组织的合法管理员预置 | 区分管理员角色通过后的跨组织 404 与普通用户 403 |
| anonymous | 无 Cookie 的独立客户端 | 未认证正反对照、公开探针 |

公开注册当前固定 `org_bootstrap`，不能靠在注册 body 加 organization_id/role 指定组织或提权。测试夹具预置第二组织须记录渠道及边界，不声称验证了不存在的“组织管理/邀请/用户删除”页面。共享环境不修改真实用户角色；缺管理员身份只阻塞管理员分支。

每次创建资源立即登记 `批次、case/子分支、身份/组织代号、资源类型、资源 ID、依赖 ID、创建时间、清理动作、保留原因`。本轮资源可按 CLEAN-01 完成批准无害动作、回答问题、取消、删除、撤销，不沿用历史“每次点击都等即时确认”的限制；全局配置/故障演练必须落在已确定的专用环境。没有产品删除入口的用户/Agent/Dataset/Artifact 仅登记保留或经既有运维流程处理，不能擅自直接删库。
