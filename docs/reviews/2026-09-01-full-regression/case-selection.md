# TypeSafe 辅助选例：规则、判断与本轮取舍

2026-09-19；对应 [案例主文档](test-cases.md) 的 95 个案例。核对当前分支 HEAD `480bf65d5bae8bf674599755e7469991c2ac0c38` 与已有 dirty 源码，全部为待执行设计。

## 1. 使用方式与模型边界

本轮已读取 `typesafe-ai` skill 及 TypeSafe 在线文档，采用“先确定候选与证据，再拆成窄问题，最后用明确规则组合”的方法检查案例。TypeSafe 的 System One 服务使用 Jev；本轮按用户“只用 deepseek-flash”的限制，不调用 Jev、不添加 SDK/密钥、不声称取得 TypeSafe 服务评分。以下取舍是本轮依据代码的人工式审阅结论，`probability/confidence` 均未产生。

方法依据：[构建指南](https://docs.typesafe.ai/concepts/how-to-build-with-system-one.md)、[候选重排](https://docs.typesafe.ai/cookbooks/rerank_typesafe.md)。这里选择的是代表性输入、步骤和执行顺序；“全功能”本身是硬规则，不能让模型从 95 条中选 Top-K 后就声称全量。

## 2. 先锁定不可丢失的覆盖

1. 从 frontend 页面/操作、BFF 路由、Agent 应用服务、exec 字节/进程实现逐层登记；从当前分支相对旧基线的提交及 dirty 文件补充变化。
2. 每个能力必须有合法成功路径，以及适用的失败、权限、重复/并发、刷新/重启路径；每个要求有案例 ID 和可核验结果。[coverage.md](coverage.md) 是映射索引。
3. 一个旅程可同时覆盖多条案例，但证据按子断言分别记录。例如生成 Excel/Word/PDF/PPT 是四份实际交付与渲染证据；一次 Run 成功不能替代。
4. 安全/隔离、持久化、故障恢复和本分支变化必须保留，即使不常被最终用户主动触发。没有环境记阻塞，不能因执行成本高而删除。
5. 已退役入口用当前入口替换；尚未实现的所需保护保留为风险断言；明确超出 flash 能力的分支登记范围限制。三者不能统称“跳过”。

## 3. 按 TypeSafe 原语拆开判断

每个候选的 state 包含：`case_id、persona、daily_task、inputs、preconditions、source_paths、branch_change、steps、expected_output、oracle、negative_controls、recovery、cleanup、model_constraint`。源码路径/ID 匹配、case 数量和模型白名单是确定性核对，不交给语义评分猜。

| 独立问题 | 对应原语及本轮审阅方式 | 决策规则 |
|---|---|---|
| 这个任务能否对应明确的日常工作？ | Noul 风格的是/否判断；不知道就登记缺角色/输入 | 将回显改成对账/交接/修订等任务，保留必要故障探针 |
| 结果能否被模型之外的资料或计算验证？ | Noul；检查来源、hash、公式、账本或明确决定 | 没有 oracle 先补，不因措辞自然就收为可执行案例 |
| 负向权限是否有同入口的合法成功对照？ | Noul；逐资源/动作检查 | “所有请求都拒绝”不能覆盖权限正确性 |
| 输入与部署是否满足 flash 限制？ | 确定性模型 ID + Noul 风格的能力条件检查 | 其它模型调用排除；缺 flash 记阻塞，不能替换模型 |
| 用户任务覆盖到了什么程度？ | Score 风格三档：仅回显；真实任务但只看文本；真实输入→操作→可打开交付→独立核验 | 补齐低档任务；安全探针不因没有办公交付被降级删除 |
| 重现步骤是否足够？ | Score 风格三档：只有功能名；有步骤但无输入/断言；有固定输入、分支、期望及证据 | 缺什么补什么，不能拿“看起来可用”作结果 |
| 该候选该如何处理？ | Choice：保留 / 改写 / 新增 / 退役替换 / 范围限制 / 需补证据 | 无匹配选“需补证据”；不能强行二选一丢失边界 |

原语语义核对：[Noul](https://docs.typesafe.ai/primitives/noul.md)、[Score](https://docs.typesafe.ai/primitives/score.md)、[Choice](https://docs.typesafe.ai/primitives/choice.md)。Noul 是“是”的概率，无单独 confidence；Score 表示按具体描述等级的位置，并非正确率。本轮只应用问题分解和具体等级的思路，不把人工标签写成模型返回值。未来若另行允许实际 Jev 调用，必须保留 state、候选、原始返回和人工复核；不能捏造一个通用置信阈值自动删案例。

## 6. 交付与覆盖局限

设计检查要求：案例 ID 唯一、上述分组无漏项、源码链接有效、历史 §4–§9 字节不变、所有新增 ID 在覆盖矩阵有归属、flash 约束覆盖每个模型入口。实际执行记录另建带日期证据；不存在本轮“产品全量已通过”的结论。

当前仍需要执行环境提供：flash 凭据/能力、管理员及跨组织身份、真实 MCP、目标 DBPM/UPDRDB/UPRedis、共享存储/VM、故障与容量预算。它们是未来执行依赖，设计本身不把缺依赖折算为通过。源码清单以本次冻结点为准，执行时出现新路由/工具/Skill 先补映射。
