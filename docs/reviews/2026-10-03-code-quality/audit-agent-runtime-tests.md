# agent 组合层与测试盘点（`src/runtime/` + `tests/runtime/` + 全 `tests/` 残留）

## 总体结论

- **盘点范围**：`agent/src/runtime/` 全量（`boot.ts`、`index.ts`、`bundle/cordis.patch.yml`、`bundle/cordis.yml`、`providers/` 19 个文件、`policy/` 12 个文件、`prompt/` 3 个文件、`plugins/` 3 个文件，合计约 7426 行）以及 `agent/tests/runtime/` 36 个 `.test.ts` + `fixtures/` 8 个探针；另盘 `agent/tests/` 全量目录的已删机制残留与 `agent/package.json` test 脚本的死引用。
- **方法**：只读。逐文件阅读 + `grep -rn`（环境无 `rg`，用系统 `grep` 替代；报告中证据命令按实际执行的 `grep` 写）查每个导出的跨包引用；对照 `cordis.patch.yml` 与 `plugins/manifest.ts` 确认按名装配的插件（「没有 import」不判死）；`ls`/`[ -f ]` 验证测试对象与脚本 glob 的存在性；`git log --oneline -3` 查可疑 fixture 历史。三个子代理并行分读 providers / policy-prompt-plugins / tests 三块，本人复核了全部关键证据（guards、render HEADER、`recordTurn`/`clear` 零调用、canonicalJson 三处、`mock-mcp-stdio-server.js` 零引用、index 引用面）。
- **总体结论**：组合层干净、无大段可删代码。确定可删仅 **1 个零引用 fixture（26 行）**；3 处纯注释漂移可改写；2 个 test 脚本的 `.test.ts` 漏覆盖可增强；其余 14 项嫌疑全部挂 fail-closed/安全/有意兼容，归入「需确认」，即使全接受也只再减约 30 行。**预计可删总量级：几十行（确定 26 行 + 待确认约 30 行），无文件级删除**（唯一候选删除就是那个 26 行 fixture）。`boot.test.ts`、`mcp-live.test.ts`（及同为真实子进程的 `agent-version-policy-live.test.ts`、`mcp-host-args-live.test.ts`）必须保留。
