# api-server 只读代码盘点

## 范围、方法与总体结论

- **范围**：`api-server/src/` 与 `api-server/tests/`。判断 BFF 路由是否仍被使用时，对照 `frontend/src/shared/api/*.ts` 的实际 URL，并核对 `docs/api.md`。
- **方法**：先读 `BRIEF-common.md` 与 `AGENTS.md` 第 1、2 节；全程只读，使用 `git status --short`、`find`、`sed`、`grep`、`wc`、`python` 读文件，未运行测试/构建，避免生成或覆盖 `api-server/dist`。
- **总体结论**：BFF 主体结构清楚，但确实存在大量旧运行时/旧 API 形状残留。最集中的风险是 `agent-client.ts` 21 处几乎相同的错误映射、两处安全相关的 `X-Acting-*` 剥离逻辑、`reviews.ts` 重复实现 JSON body 读取，以及若干前端已不再调用但仍由测试和 `docs/api.md` 保留的 BFF 路由。
- **预计可删行数**：有充分证据可直接清理的约 **230 行**（含测试）；另有约 **320 行**属于兼容/外部 API/安全相关，需确认后处理。
