# Historical reviews

These files are point-in-time audits and acceptance notes. They are retained
for traceability, but they do not describe the current implementation unless a
finding is re-verified against the current branch.

Use the following sources for current state, in order:

1. [`../../plan.md`](../../plan.md) and active ADRs
2. [`../../STATUS.md`](../../STATUS.md)
3. Active architecture, API, deployment, development, and runbook documents
4. Code and automated tests

When an archived review conflicts with current code, code wins and the active
documentation should be corrected in the same change.
