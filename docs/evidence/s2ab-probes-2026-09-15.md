## 改动要点

- agent：`bootstrap/worker-probe.ts`（`/health`、`/ready`，其余 404；端口解析非法拒启；依赖探测 2s 超时、不回显错误）；`worker-main.ts` 在容器启动前起 listener，消费者启动后置就绪，SIGTERM 先摘除就绪，启动失败关闭 listener。
- exec（facade）：`ContextStore.ping`、`SandboxBridgeClient.sandboxReady`（不带桥 token）、`McpFacadeService.readiness`、`GET /ready`。
- Compose：`agent-worker` 增加 `expose: 4101` 与基于 `/health` 的 healthcheck，不发布端口。
- 文档：`deployment.md`（探针表、变量表、Sandbox readiness 现状）、`.env.example`、design §9.2、CHANGELOG。

## 未做 / 边界

- 单测在宿主 Node v23.11.0 上运行，未在容器内复跑；运行栈容器为 Node v22.23.2。
- 回归用例与实现同批编写，未在实现前单独运行（新增能力，无修复前行为可对照）。
- SIGTERM「先摘除就绪再停消费」只由代码顺序保证，未在运行栈中抓到关停窗口内的 `/ready` 503。
- design §9.2「readiness=false 时暂停取新任务」未实现；依赖故障期间 Worker 仍会从 BullMQ 取任务，由既有 lease / fence 兜底。
- facade `/ready` 不证明窄桥 token 有效；执行面 `/ready` 修复前，其 `sandbox=ok` 只等于执行面进程可达。
- 探针端口在 K8s 中的 NetworkPolicy、LB 不注册，以及双集群 / VM 部署验收，都依赖 S0 平台信息，未做。
