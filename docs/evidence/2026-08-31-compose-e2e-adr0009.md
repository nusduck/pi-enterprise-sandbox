## 端到端抓到的五个缺陷（单测全绿时它们都在）

### 1. `remote-fs-search` 的 `parameters` 抄成了出厂 `defineTool()` 的简写

第一次开 Run 就撞上：

```
DSH agent/error: Invalid schema for function 'glob':
{"type":"string","required":true,"description":"Glob pattern to match…"}
```

出厂 `dsh-tool-fs-search` 写的是 `{ pattern: { type, required, description } }`
——那是 `defineTool()` 的**入参**形式，由它转换成 schema。我们直接调
`ctx.tools.register()`，写进去的就是最终 schema。

**为什么单测抓不到**：注册照样成功、名字照样出现在注册表里、H2.7 的「恰好相等」
照样通过。只有真开一轮时模型提供方才会拒，而那时**整个 Run 失败**。

修完第一版还错第二次：`required: true` 内联在属性上也不合法，必须是**顶层
`required` 数组**。最终形状是照抄出厂 `read` 注册后 `tools.schemas()` dump 出来的
真实结构，不是照文档猜的。

**已固化**：`boot-composition-probe` 现在检查每个工具的 `parameters` 是合法 object
节点，且属性上不得出现 `required`。

### 2. 工具执行的 durable 账本没接（第六处同族断链）

Run 跑成功、文件真的落盘，而 `tool_executions` **一行都没有**。
`recordToolStarted/Ended` 与审批、子 Agent、风险表一样，此前只经
`extensionBundleFactory` 到达运行时。已按 Run 接到 `tools/execute` 环绕上。

### 3. 账本失败被静默吞掉

第一版把记账错误 `.catch(() => undefined)` 了。「不打死一次合法调用」是对的，
但**吞掉痕迹**让 `tool_executions` 里留下永远 `RUNNING` 的行而没人知道为什么。
改成吞掉但打日志。

### 4. `findResolvedByDigest` 只有委托，没有实现

批准之后续跑**又停泊了一次**。`GovernanceApprovalStore` 把这个查询委托给
`deps.findResolvedByDigest`，而 executor 从来没提供——单测用
`InMemoryApprovalStore`（它自己实现了）所以全绿。

顺带发现一处更细的错：durable 侧存的是 `integrityFingerprint`（账本的算法），
而策略层算的是 `digestArgs`。拿后者去查 MySQL 永远查不到。接口因此改成把
**args 本身**传下去，由实现按 durable 侧的算法算。

### 5. 草稿根「字段都有、就是没人填」

`WorkspaceContext.draftSkillRoot`、`writableRoots()`、MountPlan 全都写好了，
但 exec 的 HTTP 装配没有填这个字段，`app.ts` 也没有从环境读它。
模型第一次往草稿写时报的是：

```
path escape detected: absolute path outside sandbox roots: <workspace>-draft/greeter/SKILL.md
```

——**路径围栏根本不认这个逻辑前缀**。`SandboxPathScope` 只有 `workspace` / `temp`
两个值，加了第三个 `skill-draft` 才通。

这一条最能说明「断言组合结果，不是断言配置意图」的必要：类型、纯函数、挂载计划
三层单测全绿，而这条路在真环境里从第一步就断了。

## 一次看起来像 bug 的正确行为

批准之后 Run 又停泊了一次，一度以为是续跑没生效。查 `tool_executions` 才看清：

| 调用 | 参数 |
|---|---|
| 第一次（我批准的那个） | `env \| grep DSH_`（模型在探索环境） |
| 续跑时发的 | `echo PARK_RESUME_OK` |

**参数不同 → 指纹不同 → 按 ADR 0009 D5 必须重新问人。** 系统行为完全正确，
是我的脚本批准了「上一次问的那个」。这正是 D5「人点同意之后、真正落地之前，
args 指纹对不上必须拒绝」想要的效果。

## 没跑到的部分（如实记）

- **LLMIO 网关余额耗尽**（`DSH agent/error: Insufficient Balance`），模型驱动的
  场景到「草稿建 skill」为止。**启用那一幕改为不经模型直接验**：在 agent 容器里
  调 `manager.enable()`，走的是同一条闸门代码。
- **启用没有 HTTP 路由**：`manager.enable()/disable()` 已实现并验证，但还没有
  给人点的那个按钮接出去。这是 H6.7 的下一步，不在本计划的清单里。
- **一个已知边界**：并发工具里若有一个撞审批，`agent.cancel()` 会中止整轮，
  当时在飞的另一个工具留在 `tool_executions` 的 `RUNNING` 上。停泊设计的固有边界，
  记在这里，不在本轮处理。
